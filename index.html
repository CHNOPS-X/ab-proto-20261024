토글 — 화면 맨 위 띠(위에서 약 38px)의 버튼 4개

버튼(키)하는 일
[G] (G) 왼쪽 첫 칸안경 규격 켜기/끄기 — 600×600 정사각형 · 검정 배경 · 고대비. 다시 누르면 일반 360×640. 켜면 입력이 토글 방식으로 바뀐다
[M] (M) 둘째 칸입력 방식: 길게 누르기 ↔ 토글(같은 발 한 번 더 누르면 풀기)
[C] (C) 셋째 칸오디오 시계 방식 전환(곡 밖에서만). 판정 문구에 방식별 평균 오차(ms)가 나온다
[P] (P) 넷째 칸자동 시연 — 손대지 않고 화면만 비교할 때
(B) 키보드만블라인드 정지 장면 6개(글자 없이 높이·줄 상태만)

측정할 4가지 — 화면 어디를 보면 되나 (360×640 기준)

#항목볼 곳질문
1예고 박자 수위쪽 예고 레인(위에서 약 80~190px). 노트가 위에서 나타나 노란 판정선(약 182px)으로 내려온다노트가 나타날 때 다음 동작을 알아차리는가? 판정선 몇 박 전에 알았는지 적어 달라(노트는 5박 = 2.5초 전에 나타난다)
2높이 3단계 구별가운데 무대(약 240~490px)의 줄 높이·말뚝 눈금·다리 관절 기준선. 0~11박 발목, 12~23박 무릎, 24~35박 높은 줄글자 없이 발목·무릎·높은 줄이 구별되는가? ([B] 정지 장면에서도)
3줄 상태 가독성가운데 무대의 줄 모양과 두 발(왼발 파랑, 오른발 주황)기본(직선) · 한 발 걸기(V자) · 다리 꼬기(X자, 6~7박·18~19박·30~31박) · 밟기가 한눈에 읽히는가?
4토글 on/off 차이맨 위 [G] 버튼과 화면 전체(배경·선 굵기·크기), [M] 버튼과 아래쪽 입력 영역[G]를 켰을 때 1~3번 답이 달라지는가? [M] 토글에서 다리 꼬기 조작이 쉬워지는가 어려워지는가?

함대가 확인하지 못한 것 — 플레이 후 값을 돌려 달라

  • 실기 폰 브라우저 동작(두 손가락 동시 입력 포함)
  • 실기 GPU의 3D 렌더링
  • 실기 오디오 지연 — [C]로 두 방식을 한 판씩 하고 판정 문구의 평균 오차를 적어 달라

주의: 빌드 안에 Poki SDK 태그(Poki 제출 규격상 필수)가 그대로 있다. 이 SDK는 실행 중에 광고·지오 호스트 9곳을 부르고, 곡이 끝나면 광고 시점 호출(commercialBreak)이 나간다. Poki 승인 도메인이 아닌 곳에서는 "무단 호스팅" 경고를 낼 수 있다. github.io에서 실제로 어떻게 되는지는 확인하지 못했다. 게임 코드 자체는 외부 요청 0건이다(SDK를 막은 실측).

쿠키 거부 로그 4건은 게임 코드가 아니라 Poki SDK가 불러온 Prebid sharedId 모듈 기록이다. 린터 error 0은 외부 요청 0건을 보증하지 않는다: 런타임 외부 URL 검사 결함과 쿠키 API 검사 누락이 있다.
